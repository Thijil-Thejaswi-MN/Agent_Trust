# AgentTrust: MongoDB Data Model & NoSQL Layer Architecture

This document defines the schema design, indexing strategy, and academic rationale for the NoSQL database layer in AgentTrust.

---

## 1. Architectural Rationale: Why MongoDB for Interaction Payloads?

In modern multi-agent systems (A2A), autonomous agents interact across diverse protocols (`gRPC`, `REST/JSON`, `WebSocket`, custom agent protocols). Each agent domain exchanges dramatically different data shapes:
- **Financial Agents**: Structured transactional batches with idempotency keys, ISO-20022 elements, and cryptographic signatures.
- **Healthcare Agents**: HL7/FHIR health messages with nested diagnostic codes and clinical summaries.
- **NLP / Reasoning Agents**: Prompts, token distributions, context windows, and tool call invocations (`function_call` trees).
- **Security Agents**: System-level telemetry, memory dumps, network port sweeps, and binary audit buffers.

### Limitations of Rigid Relational Models (PostgreSQL DDL):
If we forced these polymorphic payloads into a single PostgreSQL relational table, we would encounter:
1. **Schema Rigidity & Alter Fatigue**: Adding or changing agent protocols would require constant `ALTER TABLE` DDL migrations, locking tables in production.
2. **Sparse Columns**: A relational table trying to accommodate all protocol fields would be dominated by `NULL` columns.
3. **Storage Overhead on High Ingestion**: High-throughput agent streaming creates high write volumes. MongoDB's document model with WiredTiger compression efficiently compacts varied JSON structures without table-level relational constraints slowing down bulk streaming.

### The Hybrid Architectural Boundary:
- **PostgreSQL**: Governs the relational spine where strict ACID guarantees, foreign keys, triggers, and transactional state isolation are required (`agents`, `policies`, `violations`, `quarantine_events`, `risk_scores`).
- **MongoDB**: Serves as the flexible payload archive (`interaction_logs`) storing the verbatim raw messages, headers, and traces.

## 2. Collection Schema: `interaction_logs`

Each document in `interaction_logs` represents the full audit trail of an agent communication:

```json
{
  "_id": ObjectId("6718cf23..."),
  "interaction_id": "d0000000-0000-0000-0000-000000000001",
  "agent_id": "b0000000-0000-0000-0000-000000000001",
  "timestamp": ISODate("2026-10-23T06:00:00.000Z"),
  "headers": {
    "host": "mesh.agenttrust.internal",
    "user-agent": "AgentTrust-Mesh-Sidecar/2.4",
    "content-type": "application/json",
    "x-trace-id": "trace-mesh-1-1001",
    "x-request-id": "req-1"
  },
  "raw_payload": {
    "audit_scope": "api_endpoint_integrity",
    "tls_fingerprint": "TLS_AES_256_GCM_SHA384",
    "jwt_claim_verified": true,
    "client_cert_valid": true
  },
  "trace_id": "trace-1-m3h5k"
}
```

### Field Definitions:
| Field | Type | Description |
| :--- | :--- | :--- |
| `interaction_id` | `String` (UUID) | Foreign key pointing to `interactions.interaction_id` in PostgreSQL. |
| `agent_id` | `String` (UUID) | Foreign key pointing to `agents.agent_id` in PostgreSQL (source agent). |
| `timestamp` | `Date` (ISODate) | Event generation timestamp. |
| `headers` | `Object` | Arbitrary HTTP/mesh headers (e.g. tracing IDs, bypass flags, security tokens). |
| `raw_payload` | `Object` | Verbatim agent message payload with polymorphic structure. |
| `trace_id` | `String` | Distributed tracing correlation identifier. |

## 3. Indexing Strategy

To guarantee sub-millisecond lookups across millions of message documents, the following indexes are maintained:

1. **`{ interaction_id: 1 }` (Unique Index)**:
   - **Purpose**: Enables $O(1)$ single-document retrieval when a compliance auditor clicks an interaction row in the UI to view its raw payload.
   - **Constraint**: `unique: true` guarantees exactly one payload log per SQL interaction.

2. **`{ agent_id: 1 }`**:
   - **Purpose**: Rapidly filters all payload logs generated by a specific agent.

3. **`{ timestamp: -1 }`**:
   - **Purpose**: Powers real-time streaming feeds and chronological pagination.

4. **`{ agent_id: 1, timestamp: -1 }` (Compound Index)**:
   - **Purpose**: Optimizes queries browsing an individual agent's historical communications ordered by time, eliminating sorting overhead.

## 4. Anomaly Detection Aggregation Pipeline

AgentTrust leverages MongoDB's Aggregation Framework to surface payload-level anomalies that bypass basic latency checks:

1. **`$project`**: Extracts signals:
   - `has_bypass_header`: Detects presence of `x-bypass-governance`.
   - `has_large_payload`: Flags payloads exceeding 50KB.
   - `has_suspicious_command`: Flags dangerous system shell commands or memory dumps in payloads.
   - `has_error`: Flags error payloads.
2. **`$group`**: Aggregates by `agent_id`, accumulating event counts and latest activity timestamps.
3. **`$project`**: Computes an operational `anomaly_score`:
   $$\text{AnomalyScore} = 40 \times \text{SuspiciousCmds} + 30 \times \text{BypassHeaders} + 20 \times \text{LargePayloads} + 10 \times \text{Errors}$$
4. **`$sort`**: Sorts offending agents in descending order of threat score.
